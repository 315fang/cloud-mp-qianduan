## 1. 项目背景与技术约束

### 1.1 技术栈（硬约束，不可更改）
- **微信原生小程序**：WXML + WXSS + JS（不使用 Taro / uni-app / Vue / React）。
- **后端**：微信 CloudBase 云函数。接口真相源为：
  - `cloud-mp/docs/audit/generated/MINIPROGRAM_ROUTE_TABLE_AUDIT.md`（全量路由表）
  - `miniprogram/utils/requestRoutes.js`（路由到云函数映射）
- **不要**引入任何 npm UI 组件库（如 Vant Weapp、TDesign），除非现有项目已集成；优先用原生组件 + 自定义样式。

### 1.2 实现边界（首批范围）
首批**只实现以下 5 个页面**：

| 序号 | 页面 | 路径 | TabBar |
| --- | --- | --- | --- |
| 1 | 首页 | `pages/index/index` | 是 |
| 2 | 分类/商品列表 | `pages/category/category` | 是 |
| 3 | 商品详情 | `pages/product/detail` | 否 |
| 4 | 购物车 | `pages/cart/cart` | 是 |
| 5 | 我的 | `pages/user/user` | 是 |

**明确排除**（后期单独设计，本批严禁实现）：
- 订单、售后/退款流程
- 钱包、佣金、资金账户
- 分销工作台、团队、提现
- 支付相关交互（下单后的 prepay/pay-status 等）

> 在「我的」页面中，凡指向订单/钱包/分销/售后的入口：**保留入口 UI，但点击仅 `wx.showToast({ title: '功能开发中' })`**，不跳转、不调接口。

### 1.3 设备适配
- 设计基准：iPhone（375pt 逻辑宽度），单位统一用 **rpx**（750rpx = 屏宽）。
- 换算：设计稿按 375px 标注时，`1px = 2rpx`。本规范中所有尺寸**直接给出 rpx 值**，Codex 无需换算。
- 顶部安全区：使用 `{{ statusBarHeight }}` 或 `padding-top: env(safe-area-inset-top)`。
- 底部安全区：TabBar 页与含底部固定操作栏的页面，底部预留 `env(safe-area-inset-bottom)`。

## 2. 设计语言（Design Language）

问兰是**轻奢护肤品牌**。整体气质：克制、留白充足、金色点缀、低饱和暖色调。

### 2.1 五条核心原则
1. **留白优先**：内容区左右内边距统一 `24rpx`（详见排版文档间距系统）。卡片之间留白充足，不拥挤。
2. **金色为点缀，不为主体**：金色（`#B8973A`）只用于强调（价格、激活态、徽标、分割线），大面积底色用米白/白。
3. **深棕替代纯黑**：主文字、主按钮用 `#1A1208`（接近黑的深棕），不用 `#000000`。
4. **圆角统一**：卡片 `24rpx`，小标签/小按钮用胶囊（`full`），输入框/小卡 `12rpx`。
5. **层级用底色区分**：页面底 `#FAF7F4`，卡片 `#FFFFFF`，图片占位/次级区块 `#F5EFE8`。不滥用阴影，阴影只用极淡的一层。

### 2.2 禁止事项
- 禁止使用紫色/violet。
- 禁止纯黑 `#000` 文字与纯黑背景。
- 禁止 emoji 充当图标（图标用 image 或字体图标）。
- 禁止超过 5 种主色（见颜色文档）。
- 禁止渐变滥用；仅 TabBar 中间「问小兰」按钮、金色分割线允许轻微渐变。

## 3. 目录与文件组织规范

每个页面遵循微信小程序四文件结构：
```
pages/index/index.{wxml,wxss,js,json}
```

建议的复用资源目录（若项目已有同类目录，沿用现有）：
```
miniprogram/
├── styles/
│   ├── tokens.wxss        # 颜色/间距/字号变量（见颜色&排版文档）
│   └── common.wxss        # 通用原子类（卡片、分割线等）
├── components/            # 自定义组件（见组件库文档）
│   ├── product-card/
│   ├── price-text/
│   ├── section-header/
│   ├── tag-label/
│   ├── empty-state/
│   └── nav-bar/
└── utils/
    ├── request.js         # 已存在，统一请求封装
    └── requestRoutes.js   # 已存在，路由映射（真相源）
```

> WXSS 不支持原生 CSS 变量跨文件继承到组件内（组件有样式隔离）。变量方案见 `02-颜色&排版.md` 第 5 节。

## 4. 命名规范

- **页面/组件目录**：小写中划线，如 `product-card`。
- **WXML class**：BEM 简化版，小写中划线，如 `product-card__price`、`product-card--hot`。
- **JS data 字段**：小驼峰，如 `productList`、`isLoading`。
- **事件 handler**：`onXxx` / `handleXxx`，如 `onAddCart`、`handleTabChange`。
- **类名前缀**：组件内类名加组件前缀避免冲突，如 `pc-`（product-card）、`sh-`（section-header）。

## 5. 状态与交互通则

所有数据驱动页面**必须实现以下四种状态**，缺一不可：

| 状态 | 表现 |
| --- | --- |
| 加载中（loading） | 骨架屏或居中 loading 提示，不可白屏 |
| 成功（success） | 正常渲染内容 |
| 空（empty） | 使用 `empty-state` 组件，给出文案 + 引导按钮 |
| 错误（error） | `wx.showToast` 提示 + 可重试入口，不可静默失败 |

- 下拉刷新：列表类页面（首页、分类、购物车）开启 `enablePullDownRefresh`。
- 上拉加载：分类商品列表支持分页 `onReachBottom`。
- 所有可点击元素需有 `hover-class` 或 `:active` 态反馈（缩放 0.96 或变暗）。
- 网络请求统一走 `utils/request.js`，禁止页面内裸调 `wx.request`。

## 6. 交付与验收清单（Codex 自检）

实现每个页面后，逐项确认：
- [ ] 四文件齐全且 `.json` 中 `usingComponents` 正确引用自定义组件
- [ ] 颜色/字号/间距全部引用令牌，无硬编码散值（令牌见排版文档）
- [ ] loading / empty / error / success 四态齐全
- [ ] 所有图片有占位底色 `#F5EFE8`，`mode="aspectFill"` 或 `aspectFit` 明确
- [ ] 排除范围内的入口点击只 toast「功能开发中」，未调用支付/订单/钱包/分销接口
- [ ] 请求经 `utils/request.js`，路由名与 `requestRoutes.js` 一致
- [ ] 真机预览无报错，TabBar 切换正常
